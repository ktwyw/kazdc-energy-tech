系统与输入参数

两种方案都以相同的供液温度 Ts 向 IT 设备供给冷却液。设备持续释放恒定的显热负荷 Q。冷却液吸热后以回液温度 Tr 返回制冷系统。基准方案由冷水机组承担全部冷负荷。在另一种方案中，回液先进入室外干冷器，再由冷水机组承担剩余负荷。

基准系统参数。温度指冷却液温度或室外空气温度。

气象年数据

气象参考资料说明了文件及其来源标识。输入采用 Climate.OneBuilding 发布的哈萨克斯坦阿斯塔纳站（站号 351880）的 TMYx 气象文件。典型气象年由 2011–2025 年间选出的代表月份组成。文件中的室外干球温度范围为 $low 至 $high °C。干盘管通过显热交换将热量传给空气，因而使用干球温度。

读取程序从每条 EnergyPlus 气象（EPW）记录中提取干球温度，并保留原始年份、月份、日期和小时编号（1–24）。每行代表一小时。EPW 文件头规定当地标准时间为 UTC+6，记录中的分钟字段为 30。月度汇总沿用原始时间标签。哈萨克斯坦现采用 UTC+5，只有按日蓄冷的水箱模型会将原始时间转换为当前民用时间，以执行其控制时段。程序检查日期顺序及全年覆盖情况，遇到重复小时、缺失值或无效温度即报错。

在哈萨克斯坦城市比较中，每座城市分别用自己的 8,760 小时气象文件计算同一套设备。城市选择器显示气象站位置及编制典型年时可用的年份。2011–2025 数据集中的塔拉兹机场仅有 2011–2021 年间的 10 个来源年，阿克套有 14 个来源年。埃基巴斯图兹、科纳耶夫和塔尔迪库尔干采用 ERA5 再分析重建的温度。各城市结果均附原始文件链接。

干冷器的排热能力

额定接近温差确定了干冷器性能曲线上的一个已知点。当风机连续运行，干冷器独立承担设计负荷时，冷却液出口温度为 Ts，室外进风温度比出口液温低 A 度。此时入口冷却液与入口空气之间的传热温差为 ΔT + A = $design_diff K。

室外温度为 Ta 时，风机满速运行下的排热能力

G = Q / (ΔT + A)

Qcap = G × max(0, Tr − Ta)

对基准系统，G = $load / $design_diff = $coefficient kW/K。这一有效传热系数由一个额定工况拟合得到。更详细的换热器模型需分别求解两股流体及其换热特性。低温天气下，满速风机对应的排热能力可超过 IT 热负荷，实际利用的冷量以上述负荷为限。

在流量恒定时，冷却液的热容量流率为 Cw = Q/ΔT = $capacity_rate kW/K。若干冷器排走的热功率为 Qd，其小时平均出口液温为 Tr − Qd/Cw。冷水机组再移除剩余热量，使冷却液达到供液设定温度。由此可独立核对两台设备分担的热负荷。

风机何时运行

单独使用冷水机组时，系统始终消耗 Pbase = Pp + Q/COP = $pump + $base_chiller = $base_kw kWe。控制器将该功率与利用室外空气供冷的候选方案所需功率进行比较。

干冷器可用排热能力大于零时

Qd,cand = min(Q, Qcap),  d = Qd,cand / Qcap

Pcand = Pp + dF + (Q − Qd,cand) / COP

风机占空比 d 是风机以额定功率运行的时间占该小时的比例。在寒冷天气下，模型让风机间歇运行，并假定回路具有足够的热缓冲能力来满足小时负荷。干冷器和冷水机组联合运行时，风机整小时开启。两种情况下循环泵都运行。

只要排热能力为正，候选方案可节省的功率就是 d(Qcap/COP − F)。因此，仅当 Qcap > COP × F 时才开启风机。当两者相等或排热能力为零时，控制器让冷却液旁通干冷器。此时干冷器排热量和风机功率均为零。

干冷器承担全部负荷的温度界限

$full_c °C 室外

令 Qcap = Q，得到物理界限 Ts − A。在此温度下，风机连续运行即可承担全部负荷。

耗电持平点

$bypass_c °C 室外

令 Qcap = COP × F = $break_heat kWth，相应室外温度为 Tr − COP × F/G。

从逐时计算到全年结果

计算月度或年度电耗时，将各小时的平均功率乘以一小时后相加，再除以 1,000，把 kWh 换算为 MWh。每条逐时记录只计入一种运行模式。各项年度百分比均由年度总量计算，使各月按实际小时数和能耗加权。

期间耗电量及节电率

E [MWh] = Σh Ph [kW] × 1 h / 1,000

节电率 [%] = 100 × (Ebase − Ehybrid) / Ebase

以七月为例核对月度结果。共 $july_hours 小时，其中冷水机组停机 $july_full 小时、联合运行 $july_assist 小时、单独使用冷水机组 $july_bypass 小时。基准方案耗电 $july_base MWh，联合系统耗电 $july_hybrid MWh，节电率为 $july_saved%。

干冷器单独运行时供冷 $off_heat MWhth；在 $assisted 个联合运行小时中，干冷器又供冷 $assisted_heat MWhth。冷水机组全年供冷 $chiller_heat MWhth。这几项之和等于 IT 设备全年释放的热量。

在电耗方面，联合系统中冷水机组耗电 $chiller_mwh MWh，干冷器风机耗电 $fan_mwh MWh，循环泵耗电 $pump_mwh MWh。由各项未舍入值相加得到总电耗 $hybrid_mwh MWh。两种方案的泵耗电量相同，计算节电量之差时这部分相互抵消。两种方案的年度总电耗以及节电率的分母都包含泵耗电。

复现计算

下载并解压项目 ZIP。{{SOURCE_LINK}} 在项目根目录中，使用 Python 3.10 或更高版本及随附的气象 CSV 文件运行以下命令。计算、测试及页面构建均使用 Python 标准库。

python cooling.py --supply $supply --output results_reference
python -m unittest discover -s tests -v
python build.py

浏览器中的算例另有一套 JavaScript 测试。构建页面后，使用 Node.js 18 或更高版本运行 node --test。测试将逐时制冷计算与城市汇总结果比较，并核对能量平衡、储能约束和热泵运行限制。

在 results_reference/hourly.csv 中，检查每行的 dry_kw_th + chiller_kw_th 是否等于 IT 热负荷。将 hybrid_kw_e 列求和并除以 1,000，得到联合系统年度电耗（MWh）。统计 mode 为 dry_only 的行数，可得到冷水机组停机小时数。可供核对的结果见 reference/monthly.csv 和 reference/annual.csv。

测试涵盖寒冷时段的风机占空比、部分负荷时的热平衡、耗电相等时的控制选择、全年气象记录完整性，以及 49 个供液温度设定值下各运行模式的小时数。这些测试用于检查代码是否实现了所述模型；验证设备现场表现还需要设备与现场测量数据。
